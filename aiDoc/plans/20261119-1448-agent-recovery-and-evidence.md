# 智能体第四阶段：故障恢复与证据核验

## 当前基线与实施边界

本切片在独立 `feature/agent-recovery-stage4` 分支开发，起点为远端 `main` 的 `507c590`。已只读复制另一会话完成并复核的第二/第三阶段稳定源，在本分支合并权限检查与恢复证据；原工作区和 main 未修改，代码尚未提交。

整体目标仍见[智能体整体计划](20261119-1049-agent-overall-plan-and-sqlite.md)。第四阶段负责故障分类、有限只读重试和核查原任务/原产物，不替代第三阶段的计划批准、逐项写确认和权限检查，也不代表第五阶段真实业务流程已经验收。

## 只读重试合同

- 只对明确的超时/连接错误、HTTP 429/502/503/504、研究写锁超时以及 SQLite BUSY/LOCKED 自动重试。参数、权限、数据资格、金融门槛、未知异常和其他存储错误不自动重试；不解析异常正文猜测错误类别。
- 一个只读步骤最多尝试三次，失败后依次等待一秒、两秒。检查点保存操作哈希、次数、绝对截止时刻、下次可尝试时刻、状态和有限错误分类，不保存异常正文、凭据或另一份业务数据。
- 每次调用之前先经 SQLite CAS 保存 `calling` 和已占用次数；返回成功、失败或取消后再次保存。任何保存失败立即停止，不把内存结果当成已持久化事实。
- 新实例继承次数和等待期限；恢复到 `calling` 表示上次结果未知，转为 `unknown`，不得自动重放。只有明确保存为 `retryable` 的瞬时失败可以在原截止期内继续。
- 恢复会话和计划控制会核对本进程活跃 token：遗留调用通过新 token 隔离迟到结果。只读 `calling` 收敛为 unknown；明确 `retryable` 继承原预算转为待继续，不重新批准或扩充次数。
- 截止期限制启动和结果接纳，不声称可以强制终止底层已经阻塞的同步调用。取消阻止后续调用和下游推进，不声称回滚已开始的查询或任务。

## 确认身份与唯一事实源

服务端确认身份使用 `agent_action_v1`：`confirmation_id`、工具名、标准化参数哈希和原代码版本。参数先按工具白名单 schema 转为 JSON，再对 `{"tool": ..., "parameters": ...}` 做 UTF-8、排序键、紧凑分隔、不允许 NaN 的 SHA-256。计划批准仍不等于写授权。

原任务与业务结果分别保持主库任务审计、研究库回测和主库组合草案的既有职责。SQLite 只保留有界恢复摘要、检查点与原 ID，不引入新库、新表或行情/研究结果副本。

- 主库按完整确认 ID 查询 `agent_action.confirmation_id` 或 `operator_action.idempotency_key=agent:<确认ID>`，最多读取两个匹配以识别歧义；不使用最近一百条任务列表推测任务不存在。
- 主任务的 `_agent_action` 身份、实际参数和代码版本必须与原确认一致；维护动作还核对工具到运维动作的映射及规范化有效参数。
- 研究回测在 `BacktestRepository.create_run` 首次 flush 前写入 `BacktestRun.parameters._agent_action`。包括内部失败提交在内，首次持久化就带原确认身份；已有原确认产物（含失败运行）不能再次创建。该路径全程持既有研究写锁。
- 组合草案在原主库事务的 `input_snapshot._agent_action` 保存同一身份，并保留既有 `agent:<确认ID>` 幂等键；恢复还比对主任务结果的真实 `plan_id`。
- 旧任务、旧回测和旧组合若缺原确认身份，保持不可核验；不根据当前数据、相似参数或主任务声称的 ID 补造血缘。

## 跨库半提交与受控恢复

核验只读取原记录，不调用 `start` 或 `execute`，不改写原任务状态，不重新采集或重算回测。

| 原任务与产物事实 | 核验结果与后续 |
| --- | --- |
| 任务缺失，但研究产物存在 | 展示原产物 ID，保持 unknown 和阻断 |
| 任务 running，研究产物已成功 | 展示产物，继续等待主任务，不重放 |
| 任务 failed/partial 或租约完成状态 unknown，研究产物已成功 | 保留产物并展示原失败/未知状态，阻断下游 |
| 确认重复、身份冲突、参数变化、结果 ID 与产物不一致 | conflict，需诊断/重新规划 |
| 主任务 success，但所需研究/组合产物缺失或未成功 | unknown，不能仅凭任务 success 推进 |
| 主任务完整 success 且原任务/必要产物身份和 ID 一致 | verified，仅表示原任务与产物身份核验通过 |

核验不提升 `evidence_qualified`、历史 PIT、公司行为、历史 ST/退市或策略资格，不把身份核验写成研究目标达成。过期、代码变化或已取消的计划仍可只读核查原事实，但核查不能延长有效期或重新授予执行权限；新动作必须重新规划并获得新确认。

## 验证与后续验收

当前恢复核心覆盖：类型化瞬时失败、永久错误零重试、尝试前后保存失败、SQLite 新实例恢复次数/等待期、调用中断未知、取消与迟到成功、超时、旧任务精确查询、重复确认、研究首次提交身份、研究已提交后主库事务回滚、失败/部分/未知任务、旧产物不补血缘、组合身份与结果 ID 冲突、运维首次提交身份及旧任务拒绝回放。

`POST /agent/plans/{plan_id}/recovery` 接收原会话、版本、哈希和步骤 ID。恢复先保存观察检查点、结束 SQLite 事务并释放锁，再核查原任务；返回后重载最新修订并保存结果，不覆盖并发取消。当前进程仍在执行的调用不能并发核验，重启后遗留的 starting 可以只读核查。核验一个步骤不能清除其他失败/未知步骤造成的整体阻断；原任务后续转成功也不会绕过该限制。

前端恢复证据组件已接入计划面板，展示只读尝试次数、错误类别、原确认/任务/产物 ID 和既有详情入口，按钮称为“核验原任务与产物”，明确不会重新执行。真实 FastAPI、SQLite/DuckDB 与浏览器在隔离样本中完成半提交核验、失败任务保留已有 run_id、只读首次超时后第二次成功及刷新恢复次数；模型返回与业务数据是固定验收样本，未调用生产采集、正式回测或外部模型，不替代第五阶段真实业务验收。

回退保持 `AGENT_WRITE_ENABLED=false` 并禁用恢复入口，保留原任务、研究产物与 SQLite 检查点；不删除业务数据、WAL 或确认来源证据。
