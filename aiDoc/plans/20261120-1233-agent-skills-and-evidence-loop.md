# 智能体技能加载与材料验证循环

## 目标与范围

用户要求借鉴Claude Code，支持Skill及根据结果继续判断。承接既有计划、逐项写确认和第五阶段证据，不替换业务计算、事实源与审计。参考[Claude Code运行机制](https://code.claude.com/docs/en/how-claude-code-works)、[技能机制](https://code.claude.com/docs/en/skills)和[Agent Skills标准](https://agentskills.io/home)，不声明能力等价。

## 包与上下文

- 发布根为`backend/app/agent_skills/<name>/SKILL.md`。协议入口固定使用SKILL.md，属于运行资源；历史决定仍按本目录时间戳命名。
- 支持标准name/description及可选license/compatibility/metadata，正文和`references/*.md`。暂不支持Claude专用扩展、脚本、动态命令、安装上传和任意路径访问，不能声称外部Skill即放即用。
- 目录仅暴露名称与用途；`load_skill`按需提供正文/资料清单，`read_skill_reference`读取包内登记资料。上下文工具独立于业务TOOLS，不能成为执行计划步骤。
- 拒绝路径逃逸、符号链接和Windows目录联接。上限：文件16KiB、包64KiB/24项、目录16技能；每轮3技能、6次上下文调用。
- 查询与规划均支持模型自然选择及`/技能名 需求`显式选择。规划只生成草稿，不调用业务工具；缺参数仍补问。
- 正文仅在瞬态模型请求中，agent.db只保存身份与有界检查摘要，不复制正文或参考资料。

## 身份与授权

正文和参考资料的内容哈希由服务器生成。计划skills冻结实际加载的身份，参与原计划哈希；空skills省略散列以兼容旧计划。模型不能自报加载身份。

技能变化经snapshot使计划过期，推进、确认前后与后台validate_grant均重验；旧任务按原审计核查、不重放。Markdown不在Python指纹内，必须额外核验包哈希。默认写关闭，技能不是事实、参数来源、长期记忆或执行授权。

## 检查与后续判断

查询采用读取→观察→verify_skill→按缺项补查→解释/说明不足。模型只提交名称及可选resource_id，不能提交证据或判定。只使用用户明确的证券或资源ID，加载前未核验查询不追认为技能证据；同参数查询本轮去重，显式核验最多4次，原模型轮数上限继续适用。首版每技能单资源，多资源须分别提交；写动作转为新计划和原确认流程。

计划执行仅核查批准步骤中的实际观察，不自动追加步骤；补查由查询或新计划承接。结果为ready_to_explain/needs_evidence/needs_input，附task_check_complete、原引用、缺失项、限制和实际观察时刻。goal_verified固定false。刷新/重启保留原观察时刻；技能漂移清空计划执行的当前材料判定，查询历史报告保留原版本身份与观察时间。

| 技能 | 必需材料与限制 |
| --- | --- |
| data-quality-diagnosis | 概览时刻/状态/严重度统计，问题列表total/limit/offset及ID。列表仅open，概览严重度含open/reopened，最近样本可含其他状态；空样本不表示全市场无问题。 |
| factor-backtest-review | 指定成功run_id、日期、代码/数据版本、原绩效与费用合同；缺材料为needs_evidence，无基准不生成超额收益，不认证策略。 |
| position-risk-review | 指定book_id、原报价日及缺价/陈旧/流水异常、原集中度/行业覆盖；缺原诊断或摘要过大保持材料不足，空仓不等于风险认证。 |

金融指标由原确定性服务提供，不让模型重算。
