# 自动选股、持仓管控与策略自进化路线图

> 目标：把 Stock Master 从量化投研中台演进为可自动选股、自动管理持仓、并通过持续回测优化策略的量化工具，仅用于选股研究与持仓管理。
> 边界：不连接券商、不做实盘自动化交易；实际下单由人工在外部券商终端完成。
> 时间跨度：约 24-36 个月
> 前置条件：V4 研究闭环的金融正确性硬门槛必须先满足。

## 0. 前置硬门槛（不完成不进入阶段 1）

在启动自动选股之前，必须解决以下问题：

1. **财务/基本面因子时点正确性**
   - 所有基本面因子必须能追溯到公告日或首次可得时间
   - 报告修订必须保留版本，只在修订公布后使用新值
   - TTM 只由当时已公开的季度数据计算

2. **A 股真实交易成本与可交易性**
   - 卖出印花税 0.05%
   - 佣金含最低佣金
   - 过户费、规费
   - 涨停不可买入、跌停不可卖出
   - 停牌日无行情
   - ST/*ST 5% 涨跌停限制

3. **滚动 walk-forward 验证**
   - 至少支持月度滚动
   - 训练期与测试期严格分离
   - 记录每个窗口的绩效

4. **组合风险预算**
   - 行业集中度约束
   - 风格暴露（Barra 风格或自研风格）
   - 基准跟踪误差（对指数增强策略）

## 阶段 1：自动选股闭环（3-6 个月）

### 目标

每日收盘后自动生成选股信号，供人工查看并进入持仓推演。

### 交付物

1. **选股 universe 服务**
   - 输入：当前交易日、证券主数据、交易状态、停牌表、ST 表
   - 输出：可交易证券列表
   - 规则：上市 > 120 日、非 ST/退市、未停牌、流动性达标

2. **策略信号服务**
   - 每日读取最新因子值
   - 运行 `MultiFactorStrategy` 或其他模板
   - 生成 `target_weight` 或买入列表
   - 写入 `strategy.signal` / `strategy.signal_batch`

3. **信号调度器**
   - 每日收盘后触发
   - 依赖 `daily_loop` 完成后执行
   - 失败时写入 `system.job_log`

4. **信号查询 API**
   - `GET /strategy/signals?date=&strategy=`
   - 支持按策略、日期、证券过滤

5. **前端/通知（最小化）**
   - 只读展示当日选股结果
   - 可接入邮件/企业微信告警

### 阶段门

- [ ] 连续 20 个交易日自动生成信号
- [ ] 信号可追溯到因子版本、数据版本、代码版本
- [ ] universe 过滤规则有单测覆盖
- [ ] 失败信号有日志和告警

## 阶段 2：自动持仓管理（3-6 个月）

### 目标

把选股信号自动转成目标组合，并在模拟推演中执行与验证。

### 交付物

1. **再平衡触发服务**
   - 定期再平衡：每日 / 每周 / 每月
   - 阈值再平衡：权重偏离 > X%
   - 事件再平衡：universe 变化、ST/停牌

2. **组合计划生成**
   - 读取当前持仓与现金
   - 调用 `PortfolioBuilder`
   - 输出目标持仓与订单

3. **真实成本模型**
   - 升级 `linear_commission_v1` 到 `a_share_cost_v1`
   - 包含印花税、最低佣金、过户费

4. **可交易性检查**
   - 涨停不可买入
   - 跌停不可卖出
   - 停牌日无行情
   - 买入数量受限于当日可买量 / ADV

5. **模拟推演全自动运行**
   - 信号 → 组合 → 风控 → 确认 → 推演
   - 日终更新持仓、现金、净值
   - 输出归因与风险报告

6. **持仓查询 API**
   - `GET /paper-accounts/{id}/positions`
   - `GET /paper-accounts/{id}/equity`
   - `GET /paper-accounts/{id}/performance`

   2026-10-23 进展：positions 与 performance 已落地（绑定可信行情估值与权益快照序列，见 `roadmap.md` V5.4）；equity 端点由既有 equity-snapshots 承担。同时先于本阶段交付了手工记账的真实持仓账本（独立 SQLite）与草案偏离检测——这是「比较当前持仓与目标持仓」步骤的数据基础。阶段 2 其余交付（再平衡触发服务、组合计划生成、模拟推演全自动运行）未启动，阶段门不勾选。

### 阶段门

- [ ] 连续 3 个月全自动模拟推演运行
- [ ] 每日再平衡结果可解释
- [ ] 真实成本下绩效可接受（夏普 > 0.5，回撤 < 25%）
- [ ] 失败订单有明确原因记录

## 阶段 3：策略库与滚动评估（6-12 个月）

### 目标

管理多个策略，用 walk-forward 评估，人工选择是否上线。

### 交付物

1. **策略模板注册机制**
   - `strategy.template` 表
   - 模板接口：`generate_signals(frame, universe, params) → target_weights`
   - 支持因子选股、指数增强、行业轮动等模板

2. **参数空间批量回测**
   - 对同一策略的不同参数组合批量跑历史回测
   - 输出参数网格结果

3. **滚动 walk-forward 执行**
   - 月度或季度滚动窗口
   - 训练期、验证期、测试期严格分离
   - 每个窗口记录绩效和风险指标

4. **策略绩效数据库**
   - `strategy.backtest_result_rolling`
   - 按策略、参数、窗口聚合

5. **过拟合检测**
   - Bonferroni 校正
   - CSCV（Combinatorially Symmetric Cross-Validation）
   - White Reality Check 或类似方法

6. **策略下线/降权规则**
   - 连续 N 期跑输基准 → 降权
   - 最大回撤超限 → 下线
   - 换手率过高 → 标记 Review

### 阶段门

- [ ] 至少 5 个策略模板进入策略池
- [ ] 每个策略完成 36 个月以上滚动 walk-forward
- [ ] 过拟合检测通过
- [ ] 策略选择有明确人工审批流程

## 阶段 4：regime-aware 元策略（12 个月以上）

### 目标

根据市场环境动态调整策略权重。

### 交付物

1. **市场 regime 识别**
   - 基于宏观、情绪、波动率、风格收益定义 regime
   - 例如：牛市成长 / 熊市防御 / 震荡价值 / 高波动

2. **regime 下策略表现评估**
   - 每个策略在不同 regime 下的历史表现
   - 稳健性评分

3. **动态权重分配**
   - 每月初根据当前 regime 选择 top-K 策略
   - 按风险平价或等权分配风险预算
   - 切换成本控制（换手、滑点）

4. **元策略版本化**
   - 元策略选择逻辑纳入研究合同
   - 记录 regime 模型版本、策略池版本、权重分配版本

5. **长期模拟推演验证**
   - 元策略必须跑 12 个月以上模拟推演
   - 与静态策略对比

### 阶段门

- [ ] regime 识别有稳定定义和回测验证
- [ ] 元策略在不同 regime 下表现稳健
- [ ] 切换成本可控
- [ ] 12 个月模拟推演验证通过

## 项目终态边界

**本项目不设置实盘接入阶段。** Stock Master 的定位是选股研究与持仓管理：系统产出止于「研究结论 + 选股名单 + 组合持仓方案 + 风险预算 + 持仓推演」，实际下单由人工在外部券商终端完成。

因此：

- 不连接券商，不做实盘自动化交易
- 模拟盘（paper）在本项目中是**终态的持仓推演与风险验证工具**，不是通往真实账户的过渡阶段
- 阶段编号在阶段 4 之后收尾，不再有阶段 5 及之后

后续所有工作都应在上述边界内展开：改进研究结论的可信度、选股名单的质量、组合持仓方案与风险预算的合理性，以及模拟推演对真实交易摩擦的还原度。

## 关键风险与应对

| 风险 | 应对 |
|---|---|
| 过拟合 | 滚动 walk-forward、CSCV、Bonferroni、新策略 6 个月模拟推演 |
| 数据穿越 | 公告日/首次可得时间、历史行业分类、历史成分股 |
| 成本低估 | 真实 A 股成本模型、成本敏感性分析 |
| 可交易性 | 涨跌停、停牌、ST、流动性约束 |
| regime 变化 | 动态权重、策略池分散、衰减监控 |
| 数据源合规 | 明确许可范围、SLA 监控、graceful 降级 |
| 工程故障 | 幂等、审计、重跑、人工确认 |

## 推荐执行顺序

1. 先完成前置硬门槛（时点、成本、walk-forward、风险预算）
2. 阶段 1：自动选股闭环
3. 阶段 2：自动持仓管理 + 模拟推演
4. 阶段 3：策略库 + 滚动评估
5. 阶段 4：regime-aware 元策略
6. 终态：选股研究 + 持仓管理 + 模拟推演（不接入券商，不做实盘自动化交易）

**不要跳阶段。** 在阶段 1 和 2 没有稳定运行 6 个月之前，不要大规模进入阶段 3；在阶段 3 没有过拟合控制之前，不要进入阶段 4。
