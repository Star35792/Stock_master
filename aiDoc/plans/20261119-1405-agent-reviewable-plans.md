# 智能体第二阶段：意图识别与可审阅计划

## 目标与范围

承接[整体需求](20261119-1049-agent-overall-plan-and-sqlite.md)的 R4/R5，新增意图分类、缺失输入补问和计划审阅。第一阶段的会话、显式记忆、查询/预览能力继续保留；整体需求的阶段3—5继续适用。此决定取代旧计划正文中“第二阶段未交付”的状态描述，不回改旧阶段的历史验证记录。

前端 `/agent` 默认“先规划”，也可显式选“查询与解释”访问既有查询入口。生成、补问续答、批准/拒绝、历史恢复均使用同一会话。计划批准按钮标明“不会执行”；没有执行入口，不创建任务、不读取业务数据库，也不触发预检或业务写入。`AGENT_WRITE_ENABLED=false` 仍为默认值，计划批准既不改变它，也不代替将来的逐项权限确认。

## 服务端计划合同

- `POST /api/v1/agent/plans` 接收 `message/session_id`，模型只能调用一次 `submit_research_plan` 提交结构。意图为数据维护、选股研究、持仓分析、组合规划或解释咨询。结构包含目标、假设、拟读取来源、整体/逐步完成条件、参数、依赖、补问及有限结果绑定。
- `POST /api/v1/agent/plans/{plan_id}/decision` 仅接收 `session_id/version/plan_hash/decision`，决定为 `approve/reject`；不接受客户端计划正文、工具结果、角色或参数。批准只将当前可批准计划置为 `approved`。
- 计划生成不调用 `AgentTools.read/preview/start`。生成阶段的“数据来源”只是拟使用服务，不能作为已取得的市场/研究证据。模型尝试调用业务工具、未知工具、非法结构或非法依赖时整份计划拒绝。
- 模型格式不符时最多再请求一次修正（总共最多两次模型请求，每次只接收一个计划提交），服务器校验保持相同；持续无效或越权工具调用立即报错。此修正不是业务任务重试、执行循环或自动放宽参数，网络错误也不自动重试。单请求沿用 DeepSeek 有界超时。
- 服务端校验工具白名单、现有参数模型、唯一步骤 ID、依赖存在性和 DAG。仅支持依赖祖先的白名单 `task_id/run_id` 标量绑定，目标同名且类型为整数；禁止模板、任意 JSONPath 和动态绑定证券/日期/预算。绑定只声明未来输入，当前没有已核验的上游结果；后续执行必须核实业务任务和产物。
- 日期、证券、预算、因子名称/版本/方向、账本/回测/任务 ID 必须有 `input_evidence`：片段来自本会话用户消息，且包含完整参数字面值。未提供或无法核验时转 `needs_input`，清除未证实参数并列出缺口。记忆、模型回复和工具文本不代替输入来源。日期使用 `YYYY-MM-DD`，金额使用精确数字字符串，方向为 `true/false`；“上个月”“100万”等需补充明确值。此核验只证明字面来源，不是通用语义消歧、金融事实认证或执行授权。
- 参数的既有默认值由服务端追加到假设区，例如 `top_n=10`；因子方向必须明确，不自动采用既有默认方向。回测费用、数据资格、PIT 与公司行为缺口等原合同保持原状，计划文本不认证收益或策略资格。

## 冻结、失效与持久化

每份计划由服务端生成随机 ID、递增版本、UTC epoch 创建/过期时间和30分钟有效期。规范化 SHA-256 覆盖会话归属、全部计划内容、缺失输入、版本、代码版本和有效期；状态与批准时间独立存储。计划状态包括 `needs_input/draft/approved/rejected/superseded/expired`。

新规划需求先将旧待补充/待审阅/已批准计划标为被替代，并通过 SQLite revision CAS 保存，再调用模型。即使模型失败，旧批准也不会重新有效；前端重载状态，重载失败时停用批准按钮。批准前重新核对归属、当前版本、哈希、代码版本、期限及是否缺参；任何成功返回（包括重复批准）都经过 CAS，旧进程缓存不能覆盖其他进程的新版本。服务端保存失败沿用清缓存行为。

计划保存在既有 `agent_session.state` JSON，SQLite 两表不变，没有 schema 迁移、业务数据复制或跨库事务。每会话最多4份计划、每份最多8步；模型提案12KiB，服务端包络与缺失字段另限4KiB；参数嵌套最多4层、证券列表最多50项。模型假设最多8条，服务端每步最多追加一条默认说明，读合同最多16条。会话仍受256KiB/64会话总量限制；容量满时显式拒绝，不自动删除批准证据。

恢复不调用模型、不重放动作。无计划字段的第一阶段旧快照按空列表读取；过期或代码变化的计划恢复为失效。拒绝、被替代或已过期版本不能被重新批准。第一阶段动作提案的原确认接口独立存在，默认写门不变；批准计划不会确认任何旧动作。

## 验收与回退

本变更按 T2 审查，触发公共 API、跨模块计划工作流和持久 JSON 合同；架构与产品/金融边界分别独立复核。自动验证涵盖缺参/伪造来源、金融精度、默认假设、DAG/绑定、版本/哈希/过期/代码漂移、跨进程 CAS、模型失败后旧批准失效、旧会话兼容、API注入和批准零业务调用。前端核验补问续答、重复点击保护、失败输入保留和状态恢复；实际页面与真实模型验证结果在任务收尾记录。

关闭规划入口即可退回既有查询流程；旧状态文件、已批准计划及必要 WAL 保留。第一阶段程序会忽略新增 JSON 字段，回退后不得再对该会话写入而覆盖新计划证据。执行、逐项权限、有界判断循环、业务失败恢复和真实写入全流程均留到阶段3—5。
