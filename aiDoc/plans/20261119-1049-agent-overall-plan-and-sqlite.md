# DeepSeek 业务智能体整体需求与分阶段实施

## 用户目标与持续约束

用户要求把现有 Stock Master 演进为业务智能体，范围包含数据查询、采集、质量诊断和安全修复、因子研究、回测、持仓分析与组合草案。用户随后明确补充了意图识别、判断循环、会话状态、长期记忆、先规划后行动、失败兜底，以及防止模型幻觉导致越权操作。2026-11-19 用户明确选择 SQLite 保存智能体状态和记忆，并要求按整体需求逐步推进。

本文件是本需求的实施和验收清单；后续局部问题作为补充条件纳入此清单，不替换整体目标。项目硬边界仍以根 AGENTS.md 为准。

## 存储决定：独立 SQLite

- `backend/data/agent.db` 是产品智能体会话、计划、确认检查点和显式记忆的唯一状态库，配置项 `AGENT_DB_PATH`，默认相对 backend 工作目录。
- 采用独立 AgentBase，不把 SQLite 表注册到主 DuckDB；主库、研究库、持仓账本和温层继续保存各自原有事实。
- 当前两表：`agent_session`（字符串 ID、修订号、有界 JSON 快照、更新时间）、`agent_memory`（ID、分类、内容、来源会话、修订号、更新时间）。后续计划状态可纳入会话快照，是否拆表由实际查询需求决定。
- SQLite 使用 WAL、FULL 同步、5 秒 busy_timeout。CAS 更新按 ID 与旧修订号匹配并 RETURNING 新修订号；每个事务在模型或业务服务调用前结束。
- 会话最多64个、单份快照最多256KiB；记忆最多32条、每条400字符。无自动全库备份，不按时间删除必要的确认或任务证据；容量满时显式报告，后续历史整理须有引用核对。
- 只保留有界工具摘要和 ID 引用，不另存行情历史、持仓流水、完整回测产物。开发协作记忆继续放 aiDoc/memory，与产品记忆区分。
- 业务任务状态以主库任务审计为准；研究结果以研究库产物为准。SQLite 快照不构成跨库原子事务，也不证明业务任务未执行。

## 分阶段交付

### 第一阶段：状态与显式记忆

交付 SQLite 初始化、会话恢复、修订号冲突保护、历史会话入口、用户显式记忆管理，以及当前工具原型的查询和预览。提案使用跨进程有效的 UTC epoch 有效期并绑定代码版本。确认前先保存 starting 意图；若任务创建结果未知，恢复后保持阻断，禁止盲目重放。

`AGENT_WRITE_ENABLED=false` 是当前阶段默认门。现有写工具适配保留为原型，完整任务恢复和计划权限尚未验收，不能宣称全流程智能体已经完成。

验收：独立 SQLite 文件与两表；新进程/新服务实例恢复会话；CAS 拒绝旧快照；未显式保存不产生长期记忆；修改/删除检查版本；删除记忆后不再向新请求注入；过期/代码变化拒绝确认；未知创建状态不重复执行。完整真实数据业务联调留到第五阶段。

### 第二阶段：意图与可审阅计划

意图分为数据维护、选股研究、持仓分析、组合规划与解释咨询。模型提交结构化计划，服务器验证白名单、唯一步骤、参数、DAG 与有限结果绑定。计划包含明确目标、必要假设、完成条件和数据来源。冻结计划版本、规范化哈希和代码版本，用户确认后才批准。当前阶段没有交付此能力。

### 第三阶段：权限与执行状态机

依赖成功才推进；只读可在批准计划范围内执行；研究写入和数据维护步骤分别重新预检、逐项确认。服务端控制权限和状态，模型无法自行授权。工具不提供 SQL/Shell/文件凭据访问、真实账本改写、paper 审批或订单执行。限制重复调用和不产生进展的循环。此阶段通过后才评估开启写执行。

### 第四阶段：故障恢复与证据核验

仅对明确的网络、限流、临时锁等只读瞬时失败有限重试，次数写入持久状态。参数、数据资格和金融门失败不自动放宽。主库按确认 ID 精确查询任务；研究产物在同一研究事务绑定确认 ID 与参数哈希，核查跨库半提交。partial/failed/unknown 不推进下游；保留已完成产物，提供诊断、重新规划和受控恢复。取消阻止后续动作，不声称回滚已开始任务。

### 第五阶段：业务全流程验收

接真实 FastAPI 与真实浏览器，走“数据诊断和修复”“因子研究与回测”“成功回测到组合草案”“持仓只读分析”等流程。模型结论引用真实 ID、日期和原服务指标，明确区分事实与推断；写后复查实际产物，任务 success 不直接等于研究目标达成。保持 PIT、历史 ST/退市、公司行为和证据资格的既有缺口声明。

## 评审、回退与范围

本需求为 T2，触发存储、schema、公共 API、产品工作流及根规则变化。按决策评审协议分别进行架构、产品/金融和规则独立复核；测试与独立复核分别验收。当前原型不提交、不合并到 main；每一阶段都报告实际验证和未完成边界。

第一阶段没有历史产品记忆需迁移，原内存原型没有持久对话库。回退以禁用智能体入口和保留 agent.db 状态文件为主，不自动删除状态、WAL 或业务产物。后续实现不得把单纯工具调用、提示词约束或文本计划写成完整的自主智能体。
