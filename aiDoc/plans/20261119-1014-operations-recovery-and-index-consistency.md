# 运维恢复与索引读取一致性

## 触发与边界

用户发现因子计算和类似后端问题无法从前端处理。本次按 T2 实施：扩展公共动作合同及关键恢复工作流，并执行两个已证实异常索引的定向维护。产品、金融、后端及数据库方案经独立复核。保留单机单用户、可信数据与人工确认边界，不引入通用脚本执行器、外部交易或新的数据源。

## 已验证的数据库故障与修复

2026-11-19 只读核验发现，任务列表可见但索引点查遗漏 ID `343/344/352/353/354`；证券 `688845.SH` 同样漏读。禁用优化的全表读取可见这些事实，两个独立连接均复现；未发现重复任务 ID。

经独立复核后，`scripts/maintenance/repair_index_consistency.py` 持主库 OS 写锁，只修复 `uq_job_log_id` 与 `ix_compact_market_security_symbol`。先建并提交同列唯一 guard，再分事务恢复原索引，前后比较行数、全列 SHA256、原索引定义及全部键点查；完成后 CHECKPOINT 并重开数据库再验证。默认模式只读，实际修复必须指定精确索引、操作人及原因；失败输出阶段并保留必要 guard，不删业务事实或生成全库备份。

## 受控恢复动作

既有 `daily_data_sync`、`daily_bar_gap_backfill`、`factor_profile_rebuild` 保留；新增：

| 动作 | 参数 | 执行与复查 |
| --- | --- | --- |
| `factor_values_rebuild` | 仅 `original_run_id` | 服务端从原记录恢复目标窗口、证券和复权，要求相同受支持版本；当前代码建立新 run，复核目标日期、价格观察数及逐证券产出 |
| `alternative_data_sync` | `sources` 仅 `hithink` / `eastmoney` | 经现有源采集和 raw/market 校验，新建 `alternative_data_collection` 业务任务；部分来源或空数据不代表全来源恢复 |
| `price_value_input_prepare` | 默认 `{}`，预检固定 `price_date` 与 `observation_mode` | 仅最新完成交易日的 `current_research_catchup`，执行前再次核日期，准备后重生成当前研究报告并返回阻断原因 |

因子恢复必须保留完整原 `target_start_date` / `target_end_date`；`input_start_date` 已含预热，不能作为新输出起点。缺上下文、停用/退役或未知版本拒绝自动重算。资源上限为 367 个自然日、8,000 只证券、200 万条价格输入；全市场请求也检查实际证券数。计算器自身的证券适用类型保持，不把股票因子不会消费的指数误报成缺价格。

重算记录当前真实代码、实际消费价格摘要及 active trusted QFQ release/checksum，前后校验发布身份；不冒用原代码或 release。原运行与失败证据保留。无输入、预热不足或目标日期缺口预检阻断；空或覆盖不足返回 partial，并披露缺项。完成不代表 PIT、IC、池资格或可交易性认证。画像诊断只消费已有值，任一画像候选为空仍保持未解决。

任务幂等查找覆盖全部历史，启动和执行持受控写锁，重复调度拿锁后重新检查状态。前端修改参数立即使预检失效，晚到响应不得恢复旧计划；失联请求沿原幂等键重试，刷新沿 action ID 恢复。demo 禁写，快捷建议只填表，仍须预检及确认。未复权同步不承诺重建 QFQ 发布；未注册或无法安全恢复的失败明确保留人工诊断。

## 来源证据

两个 alternative 源先提交导入批次和逐响应 raw，再独立事务写 market；后续抓取、解析或标准化失败保留已收证据，market 回滚并标失败。相同来源/dataset/日期/内容哈希复用，真实变化新增版本。非法日期只按真实采集日归档 raw，明确未发布 market，不伪造业务日期。批次响应数、新增 raw 数及复用引用的口径见 `data/source-ingestion-policy.md`。

当前价格价值补采保留真实 observed_at/financial_as_of、`pit_verified=false` 与研究隔离；不能把当前研究观察补进通用估值因子或历史回测。旧日失败不回写为成功。
