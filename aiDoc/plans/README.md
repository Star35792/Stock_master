# 计划与路线 Reference

## 当前阶段

- 当前整体处于 V6.1 只读运维工作台收口后、转入 V5 公共操作闭环的阶段。
- 项目边界：**只用于选股研究与持仓管理**，不连接券商、不做实盘自动化交易、不发送真实订单。模拟盘是终态的持仓推演工具，不是通向真实账户的过渡阶段。
- V4 已完成单次回测研究合同闭环，并交付批量运行、验证区间合同、交易日窗口生成、基准/跨运行比较和同合同回归漂移诊断；训练产物血缘与窗口绑定已落地，训练选参首切片（`selection_policy=training_ic_v1`，见 [训练窗自动选参计划](20261024-1522-training-window-selection-plan.md)）已交付，跨窗编排、参数敏感性与 champion/challenger 晋级尚未形成自动闭环。
- V5.1 已交付组合手工模拟草案；V5.2 已交付只读风险前数据核对、paper 账户净值历史、服务端 ADV 和绑定不可变输入的正式风险评估；V5.3 已开放五分钟有效的人工确认、一次性原子消费和幂等模拟执行批次。当前固定 local single-user、paper-only、确定性 full-fill 和全批原子语义。
- V6.1 已有最小运维概览工作台、告警候选摘要、按分类限量的失败定位摘要、单项失败详情、只读重跑计划和前端执行前准备态；细粒度重跑执行属于后续写侧任务，需先完成权限、审计、幂等和人工确认设计。

## 近期优先级

1. 研究可信基线修复：恢复温层历史日线继承、重建 `market.prices_qfq` 视图、回测报告与落盘数字对账、研究产物纳入版本控制。
2. V4 后续研究编排：训练选参产物留痕、窗口与运行不可变绑定、参数敏感性和回归金样本。
3. V5 外部操作 API：组合、风控、持仓推演的公共 schema、稳定路由、前端工作流、人工确认和审计流程。
4. V6 写侧运维动作设计：细粒度重跑执行入口仅在权限、审计、幂等和人工确认边界明确后启动。
5. 选股与持仓管理增强：因子 IC 证据表、分层回测、组合约束进回测、偏差源补齐。

## 下一步切片边界

V4 单次回测研究合同及其支撑 API 已交付。滚动窗口按指定交易所的 `market.trading_calendar` 开市日计数；启用 `selection_policy` 时逐训练窗自动选参（预注册阈值，产物落 `training_artifact`），不启用时滚动字段记录外部训练与选参区间，不代表平台已自动完成训练或选参。回归漂移只允许比较除代码版本外研究合同一致、测试区间一致且数据版本一致的成功运行。

详细执行计划：[V4 单策略研究合同与可复现回测计划](v4-research-contract-plan.md)

## 量化工具演进路线

项目长期目标是演进为支持自动选股、持仓管控与策略自进化的量化工具。该愿景已沉淀为：

- [产品与投资者视角评估](../strategy/product-investment-assessment.md)：当前能力、核心缺口与金融正确性硬门槛
- [量化工具愿景](../strategy/quantitative-tool-vision.md)：自动选股、持仓管控、策略自进化的分层设计
- [自动选股、持仓管控与策略自进化路线图](auto-selection-position-roadmap.md)：分阶段执行计划
- [前置硬门槛执行计划](hard-gates-execution-plan.md)：自动选股前必须完成的 4 项金融正确性硬门槛，当前从 A 股真实交易成本与可交易性开始
- [研究产出最大化行动计划](20261021-1708-research-output-maximization-plan.md)：可信基线修复、因子 IC 证据表与偏差源补齐的优先级

该路线与现有 V4/V5/V6 路线是补充关系：先完成 V4 研究闭环与 V5 持仓推演公共操作闭环，再按前置硬门槛计划补齐金融正确性，最后扩展自动选股、策略库和元策略能力。全程不涉及实盘自动化交易。

## 计划文档同步规则

- 改阶段状态、优先级或交付范围时，更新 `aiDoc/plans/roadmap.md`。
- 改项目入口表达或 API 面时，更新 `README.md`。
- 改文档导航、阅读顺序或当前状态摘要时，更新 `aiDoc/README.md`。
- 临时任务计划不要写入正式文档；只在任务执行中用 todo/plan 管理。

## 决策治理

- 涉及产品、架构或金融语义的重大决策，以及 AI 代办的提交前检查，按 [决策与提交评审协议](decision-review-protocol.md) 执行。
- 评审过程保留在当前任务、提交说明或 PR 中；只有长期稳定的结论才同步到对应 `aiDoc`，不要为每次评审新建文档。
