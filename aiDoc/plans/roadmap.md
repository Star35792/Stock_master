# Stock Master 路线图

**价值初筛精选名单（2026-10-29）**：报告升级为 `relative_value_research_v7`，新增 `value_research_shortlist_v2`。保留原走势现金流条件池，另以 PE≤20、PB≤2、逐年盈利及净利润 TTM>0、上市年限、完整 20 日平均成交额、均线偏离及披露 ROE 条件形成达标池；周期行业和异常 ROE 留待复核。后台按明确估值与质量顺序安排最多 10 只、每行业最多 2 只优先研究对象，容量递延不代表不合格。页面默认优先名单，可显式查达标池和原条件池，个人过滤不补位。参数、版本、逐股原因与排序进入不可变报告；该能力未完成绝对估值或未来收益验证，完整口径见[价格价值策略](../strategy/20260922-1314-price-value-margin-strategy.md)。

**价值初筛当前补采（2026-10-29）**：显式 `current_research_catchup` 仅面向最新完整交易日的当前研究，日期接口估值先留 raw，经同日可信价格与分所覆盖校验后发布隔离研究观察。报告和页面区分行情日、财务日期、真实采集和分析时间；财务版本截至实际分析时刻。补采不补造当晚历史名单，不认证 PIT，不解除基础数据、走势、质量和鲜度门槛。

**价值初筛研究诊断（2026-10-29）**：原诊断层 `value_research_diagnostics_v1` 保留基础数据准入、读时鲜度、完整 21 个交易日的复权走势和三年盈利/现金流条件；v7 默认名单继续经过上面的精选层。数据不足和明确风险分别解释，未通过的原始记录需主动打开，零候选不自动回退。读时核验上海三所日历，保留旧报告哈希；旧版本、过期及无法核验报告不进入当前名单。研究规则与公式见[价格价值策略](../strategy/20260922-1314-price-value-margin-strategy.md)，未声称收益改善或历史 PIT 认证。冻结名单跟踪已接入，下一步是持续积累未参与调参的观察窗口，再判断门槛是否有增量价值。

**价值初筛冻结名单前向观察（2026-10-30）**：新增 `price_value_forward_observation_v1` 与只读 `screen/tracking` 接口。每次 v7 报告原子写入独立 cohort sidecar，冻结优先名单、达标池、原条件池、观察模式、实际分析时刻及原快照哈希；跟踪不改写原始大报告。`same_evening` 从目标日后的首个共同交易日、`current_research_catchup` 从实际分析日后的首个共同交易日收盘开始，固定观察 5/20/60 个交易日，以原条件池等权结果为内部基准。成员不补入、不再平衡，缺前复权价格不静默剔除；页面展示原始/可观察数、覆盖、毛收益、固定 0.1% 双边比例成本后的观察结果、相对原池差异和最大成员跌幅。观察窗未完成显示等待，不用 0% 代替未知；能力仍为研究观察，不是回测或收益认证。

Stock Master 的优先级是：先建立可复现、可审计、可回放的量化数据底座，再做因子、组合、回测和持仓管理能力。任何策略收益都不能建立在不可解释的数据误差上。

**项目边界**：本项目**只用于选股研究与持仓管理**。不连接券商，不做实盘自动化交易，不发送任何真实订单。系统产出止于「研究结论 + 选股名单 + 组合持仓方案 + 风险预算 + 持仓推演」，实际下单由人工在外部券商终端完成。

## 路线图原则

- 数据先于策略：策略只能读取 `market` 和 `factor` 可信层，不直接读取 `raw`。
- 可复现先于速度：同步、构建、修复、因子计算和回测都必须可重复运行。
- 质量先于覆盖：每扩展一个数据域，先定义契约、质量规则、缺失检测和审计闭环。
- 架构先分层，接口后稳定：按 `raw -> market -> factor -> research/backtest -> portfolio/risk` 分层演进。
- 选股与持仓管理是终点：系统不追求自动下单，模拟盘只用于持仓推演与风险验证，不代表通向真实账户。

**分层回测与多窗口组合净收益曲线（2026-10-24，2026-10-25 P0 修正）**。因子选股回测入口新增两项研究能力，均经四角色评审（架构/产品/金融/规则）裁决，不改变既有金融正确性硬门槛。其一，`POST /api/v1/strategy-research/factor-selection/backtests` 与 `/rolling-backtests` 的 `quantile_backtest` 可选参数（`split_factor_name/version`、`n_layers` 2–20、`max_assets_per_layer`、`weighting_mode`）会在单次回测/每个滚动测试窗内，按 split 因子在**决策日**的横截面排序把可投资 universe 切成 `n_layers` 个互斥桶；universe 沿用主请求 `allowed_security_types`，主数据缺失或类型不允许的证券不进入分层。各层运行等权多头 long-only 组合（T+1、含费含税），产出每层净值曲线与 top–bottom（最高减最低层）统计收益差；A 股不可做空，多空差只是**统计收益差**而非可交易空仓，结果强制声明（long_short / bias_disclosure / method / position_target_policy）。2026-10-25 修正首版两个 P0：换层时显式向旧成员发零权重退出目标，空桶同样清仓；分层分支不再复用主策略 top-N 的行情子集，而是独立读取全量层证券的可信未复权行情、公司行为与交易日历并做前后双快照校验。新结果以 `position_target_policy=explicit_zero_exit_v2` 和 `parameters.quantile_data_snapshot` 标识；缺少该声明的旧多决策日分层结果不可用于研究结论，主回测与 rolling `combined` 主曲线不受影响。分层计算不落独立 `backtest_run`，曲线与 spread 内嵌主运行 `parameters.quantile_backtest` 的 JSON、随响应返回 `quantile`；默认 `quantile_backtest=None` 时完全不写入，保持漂移可比性。其二，滚动回测新增 `RollingBacktestResult` 包装：每个测试窗仍是独立 `backtest_run`，并把各窗 test 期 equity 按首尾衔接、归一化本金（**不重置**）拼接为一条组合净收益曲线 `combined`（含再聚合的换手/佣金/夏普/回撤），重叠测试窗 fail-closed 拒绝拼接、各窗结果仍独立可用；该曲线是**研究统计量而非连续可交易策略**，训练期被排除、跨窗不结转持仓。纯函数 `partition_universe_by_factor` 与 `stitch_equity_curves` 承载分桶的确定性、互斥覆盖与拼接的本金接续及重叠守卫；分层与拼接均不重算成本（成本已在引擎逐日计入）。设计裁决、金融正确性不变量与修正记录见 `aiDoc/research/20261024-1800-quantile-and-rolling-curve.md`。已知硬缺口仍沿用在位声明：分层与回测均不扣幸存者与 ST/停牌偏差（2026-10-27 审计中停牌事件仍为空；公司行为事件会计未实现），样本仍带选择-幸存者偏差。行业时点只对 2026-11-11 之前的运行仍是当前标签近似，此后的运行按申万时点区间取值。

**估值历史研究层已落地（2026-10-26）**。此前价值因子没有任何 IC 证据：`factor.factor_profile` 只有 7 个价量因子（`v2-qfq-2y`）的记录，估值族因子从未有过逐日 IC，因此 `FactorPoolClassifierService` 无法给价值族任何分级依据，扩池首跑在 2024-2026 段因「价量族证据强度已上限」而 fail-closed（2/16 存活）。本轮通过东财 `RPT_VALUEANALYSIS_DET` 补采 2024-05-01 起的估值历史序列，发布为**温层 Parquet 研究表** `research.valuation_history`（不在控制面、无 ORM 模型、无 Alembic 迁移，判定标准见 `aiDoc/modules/schema-plan.md` §17），并配套新增 `scripts/factors/compute_value_factor_ic.py` 计算 `value_earnings_yield` / `value_pb_mrq` 两个价值因子的逐日 IC 与 RankIC，落入 `factor.factor_profile`。第三个因子 `value_pe_ttm` **已退役**（方向性错误：`-PE_TTM` 把亏损股映射成大正数，最便宜五分位 100% 是亏损股；退役证据保留在 `v1-valhist` 供审计，修正后的证据发布到 `v2-valhist`）。

采集链路上修掉了三个会静默污染数据的缺陷：（1）**分页排序**——只按 `TRADE_DATE` 排序时，服务端对同一交易日内部的行序不作保证，实测 8 个交易日的分页在第 1、2 页之间重复 571 个键并同量丢行，此前「覆盖率 0.907」其实是分页错乱造成的伪影，改用复合排序 `TRADE_DATE,SECURITY_CODE` + `sortTypes=1,1` 后跨页重复归零、8/8 交易日全部过闸门；（2）**闸门口径**——覆盖率分母原含 569 个指数 bar，而供应商只提供个股，已改为 `security_type='stock'` 口径，并新增重复键闸门（同一 `(symbol, trade_date)` 出现多次即拒收该日）；（3）**raw 证据体积**——早期版本把 1.6 MB/页的完整响应体写进控制面，一次中断的采集就把 `stock_master.duckdb` 从 726 MB 撑到 1 GB，现改为只落页级元数据（请求参数、响应 SHA256、行数、抓取时刻），明细留在 Parquet。

**这些估值历史行不是时点证据**。它们是今天采集的历史数据，全部行 `pit_verified=false`；`PB_MRQ` 按报告期末切换，最多前视 120 天。因此价值因子的 IC 只能作为「估值比率与未来收益关系」的研究证据，**不得表述为可交易证据**。字段级判定见 `aiDoc/data/20261026-valuation-history-backfill.md`。

**因子池分级新增三道闸门（2026-10-26）**。秩 IC 只说明「单调相关」，不说明「极端分位可交易」。分级器现在除 IC 与覆盖率外，还要求：

- **端点闸门**：1 日多空（top−bottom 分位）价差**严格为正**。这是可交易性的直接证据，也是本轮把 `long_short_forward_return_5d / _20d`、`quantile_monotonicity_1d`、`top_quantile_turnover` 一并落库的原因。
- **PIT 闸门（fail-closed）**：`factor_definition.pit_status` 取 `point_in_time` / `look_ahead` / `unknown`（默认）。`look_ahead` 硬冻结；`unknown` 不得进核心池。本轮审计结论：7 个温层价格量因子为 `point_in_time`（纯历史价格量），`value_earnings_yield` 为 `point_in_time`（PE 按披露日切换），`value_pb_mrq` 为 **`look_ahead`**（PB 按报告期末切换）。
- **生命周期闸门**：`factor_definition.status` 取 `active` / `retired`。`retired` 表示定义已被取代或已知有误，证据保留供审计但硬冻结。

在 2026-10-26 旧口径下，启用这些闸门后**核心池从 4 个收敛到 1 个**（`volume_stability_20@v2-qfq-2y`）：`max_drawdown_20` 因端点为负落榜、`value_earnings_yield` 因端点为负且覆盖率 0.6957 低于 0.70 落榜、`value_pb_mrq` 因 PIT 前视硬冻结。同时修掉两个基础缺陷：IC 脚本的 `session.merge` 不幂等（改用 `ON CONFLICT DO UPDATE` 的 upsert，重跑后行数不变）、`coverage_rate` 的分子分母同取因子自身非空集（改为分母取价格宇宙，`value_earnings_yield` 真实覆盖率 0.6957）。通用价值因子另按金融正确性**排除银行/保险/券商等 122 只金融行业个股**（其 PB/PE 口径与工业股不可横截面比较，且天然便宜会主导「最便宜」分位）。这是旧口径历史结果；新增证据资格闸门后，[2026-10-27 策略资格审计](../research/20261027-2122-strategy-readiness-audit.md)记录 `core=0`，不能继承旧“唯一核心”的资格。旧口径证据见 `aiDoc/data/20261026-valuation-history-backfill.md` §6.2~§6.5。

## V4 建议工作计划（量化研究 + 架构视角）

目标：把“能跑的最小回测”升级为“可复现、可比较、可持续迭代”的研究平台。

核心原则：

- 防止未来函数、幸存者偏差和样本泄漏。
- 所有研究输入都必须显式版本化，包括因子版本、数据版本、代码版本和复权方式。
- 财务、行业、政策、另类数据和宏观数据必须记录可得时间；不能用当前行业分类、当前成分或报告期结束日回填历史信号。
- 策略模板只消费 `market` 和 `factor` 可信层，不直接碰 `raw`。
- 一切结果都要可回放、可对比、可审计。

建议工作顺序：

1. 先统一研究契约
   - 固化策略输入、信号输出、调仓频率、持有期、费用模型和基准定义。
   - 让每次研究运行都带上 `strategy_name`、`signal_lag`、`rebalance_rule`、`benchmark`、`code_version`、`data_version`。
2. 再把策略模板产品化
   - 把股票池、ETF 轮动、多因子打分、指数择时整理成独立模板。
   - 为每个模板明确适用 universe、调仓频率、约束、退出规则和默认风控参数。
3. 然后扩展回测服务化
   - 在现有因子选股回测入口和回测查询 API 基础上，补齐更多策略模板入口。
   - 支持批量运行、参数组合运行和跨运行对比。
   - 对回测结果做幂等落库和回放校验。
4. 接着增强绩效归因
   - 增加样本外评估、滚动窗口、分市场状态分析和成本敏感性。
   - 把行业暴露、风格暴露、换手、回撤和收益贡献统一到研究报告。
5. 最后补齐工程化护栏
   - 持续增加回归测试金样本；当前已覆盖逐决策日 as-of、输入深冻结、次一交易日成交、缺执行行情 fail-closed、费用/滑点、顺序置换确定性、重复输入和运行期数据摘要漂移。
   - 增加结果漂移检查和版本对比。
   - 给失败运行、低覆盖因子和异常绩效生成可追踪告警。

建议的近期交付物：

- 更多策略研究入口服务和命令行入口。
- 标准化策略配置对象。
- 回测结果对比 API。
- 样本外绩效分析与基准对比。
- 回测回归测试集。

## 选股与持仓管理终态

**本项目到此为止，不进入实盘自动化交易。**

Stock Master 的交付终点是「研究结论 + 选股名单 + 组合持仓方案 + 风险预算 + 持仓推演」。系统不连接券商、不实现真实账户只读或写操作、不发送任何真实订单，实际下单由人工在外部券商终端完成。

明确不在项目范围内的能力（不作为后续路线，也不设阶段门）：

- 真实账户只读同步与券商回报对账。
- 受控交易、自动下单与外部订单幂等状态机。
- 应急开关、全局停单与账户隔离。
- 券商可交易性规则与交易所级撮合语义。

模拟盘（paper）是本项目的**终态持仓推演工具**，用于在含费、含可交易性约束下评估调仓动作的结果，不是通向真实账户的过渡阶段。任何模拟执行结果都只作为人工持仓决策的参考，不得表述为可自动下单或已验证实盘可行性。
