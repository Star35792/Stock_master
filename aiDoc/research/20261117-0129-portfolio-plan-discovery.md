# 组合草案发现与持仓偏离入口

## 现状与决策

原持仓页的偏离检测要求手输草案 ID。主库在 2026-11-17 的只读核查中有 0 份组合草案，因而日常流程首先需要明确空状态与创建入口，而不是默认存在可用草案。

新增 `GET /api/v1/portfolio/plans?limit=&offset=`，从主库 `portfolio.portfolio_plan` 只读返回 `plan_id`、名称、草案截至日、草案预算、代码版本和创建时间。按创建时间、ID 倒序稳定分页，单页上限 100；列表不复制目标明细或估值事实。完整草案仍由既有 `GET /portfolio/plans/{plan_id}` 获取，创建仍走既有幂等 `POST`。

持仓页加载最近 50 份草案，支持继续加载、刷新和手输 ID。没有草案时指向组合创建页；选择草案后显示其截至日和预算，提示与当前账本核对。偏离响应自身也携带草案名称、截至日和预算，使手输 ID 或旧草案不依赖列表页次才能核对身份；页面同时展示当前账本权益、最晚报价日，并提示日期不一致时草案可能过期。选择或账本变化会按既有代际守卫作废旧偏离结果。列表读取失败时保留手输 ID 的既有入口。

列表只负责发现草案，不代表草案适合当前账本、当前报价日或真实交易。偏离仍只读，缺可信价的非零持仓整体阻断，较早报价的解释与阈值规则沿用[偏离覆盖决策](20261117-0116-portfolio-drift-coverage.md)。

## 验收与回退

验证接口分页与排序、摘要序列化、参数上限，以及前端跨页选择和手输 ID 回退。此变更无 schema 迁移、无新持久化事实；回退仅需移除列表端点和选择 UI，不影响已有草案或账本。
