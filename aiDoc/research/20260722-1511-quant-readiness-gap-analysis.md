# 量化平台"跑起来"差距分析

- 日期：2026-07-22
- 视角：量化专家
- 范围：评估 Stock Master 从"代码具备"到"每日自动可信运行"还缺什么
- 方法：核对数据库实际行数 + 阅读核心代码（数据底座、因子框架、回测引擎、组合构建、策略层、调度器、执行闭环）

## 1. 总评

架构和数据底座扎实，但"跑起来"缺的不是代码，而是"代码写了却没在真实数据上持续运行"。大量关键表是空的或极薄的，意味着很多能力是"纸面能力"，链路没真正打通成每日闭环。

数据库实况（最硬的证据）：

| 表 | 行数 | 含义 |
| --- | --- | --- |
| `market.daily_bar` | 406 万 | 日线底座扎实 |
| `market.security` | 7678 | 股票池有 |
| `fundamental.financial_indicator` | 25.4 万 | 财务有 |
| `market.valuation_snapshot` | 0 | 估值数据完全没采 |
| `market.alternative_data_snapshot` | 2365 | 另类数据极薄 |
| `factor.factor_value` | 2.8 万 | 因子值覆盖率 <1% |
| `factor.factor_profile` | 13 | 几乎没做有效性检验 |
| `strategy.backtest_run` | 4 | 只跑过 4 次 |
| `system.job_log` | 0 | 调度从没真正跑过 |
| `system.data_quality_issue` | 0 | 质量校验没接入产出 |
| `paper_execution_approval` / `batch` | 0 | 新执行闭环未实战 |

## 2. 阻塞性缺口（不补，系统跑不起来）

### 2.1 估值数据为空 -> 估值因子域整体失效

`market.valuation_snapshot = 0`。7 个估值因子（`earnings_yield` / `book_to_price` / `fcf_yield` / `ev_to_ebitda` …）的核心输入是空的。`valuation_collection.py` 服务存在但从没真正采过数据。11 个因子域里有 1 个域完全跑不出值，复合决策分会缺一条腿。

### 2.2 因子批量计算管道缺失 -> 回测/选股没有输入

`factor_value` 只有 2.8 万条，而 7678 证券 × 729 天 × 82 因子 = 4.5 亿潜在。当前只有按需 CLI 计算入口（41 个 run），没有全市场全历史的批量计算，也没有每日增量更新。没有因子值时间序列，回测和选股就是无米之炊。这是"跑起来"最大的单点缺口。

### 2.3 没有自动化每日闭环 -> 现在全靠手动拼

`scheduler/daily_sync.py` 只调度数据同步（HiThink + 近期补齐），不调度因子计算、不调度信号生成、不调度组合再平衡。一个量化平台"跑起来"的标志是：每日收盘后 `数据更新 -> 因子增量计算 -> 信号 -> 组合再平衡 -> 风控 -> 模拟执行` 自动串起来。现在这一串是断的，每一步都要人手动触发。

## 3. 可信度短板（能跑，但结果不可信）

### 3.1 另类数据极薄 -> 上层因子域是纸面能力

`alternative_data_snapshot` 仅 2365 条。情绪、宏观、资金流、政策、盈利预期这 5 个域全部依赖它。按 7678 证券 × 729 天算，覆盖不到 0.1%。这些因子现在算出来的值要么空、要么代理，roadmap 自己也承认"多为代理变量"。它们能注册成目录，但不能进生产评分。

### 3.2 system 表全空 -> 无运维、无质量、无治理

- `job_log=0`：数据是手动脚本灌的，调度从没通过系统记录执行过，没有任务失败告警。
- `data_quality_issue=0`：406 万行日线 0 个质量问题不现实，说明质量校验要么没跑、要么没接入 ingest 流程产出问题。没有质量门，回测异常无法归因到数据。
- `data_source=0`：数据源是硬编码的，没有可配置的来源治理。

### 3.3 回测真实度不足（A 股特性缺失）

`DailyEventBacktestEngine` 有佣金(0.03%)、滑点(2bps)、整手取整、现金管理，是合格的首版。但缺 A 股关键约束：

- 涨跌停不可买（涨停板买不进、跌停板卖不出）。
- 停牌日处理（停牌期间不能交易、持仓按停牌价估值）。
- 印花税（卖出 0.05%，只建了佣金）。
- T+1（当日买入次日才能卖）。
- 容量/流动性约束（fill 用参考价 + 固定滑点，无成交量上限、无冲击成本）。

不补这些，回测收益会系统性偏高，尤其换手高的策略。

### 3.4 因子有效性检验闭环未形成

`factor_profile` 只有 13 条。没有系统化的 IC/Rank IC 衰减、分组单调性、换手率、分层收益、多空收益、不同市场状态稳定性检验。4 次回测不足以判断任何因子是否真有 alpha。因子注册成目录 ≠ 因子有效。

### 3.5 新公共执行闭环未实战

V5.1/5.2/5.3 的 `paper_execution_approval`、`paper_execution_batch`、`paper_account_equity_snapshot` 全是 0。代码和单测过了，但从没在真实数据上跑过一次。只有老 `paper_trading` 跑过 1 笔。这条链路是"测过但没验过"。

## 4. 能力增强（跑起来后再做）

### 4.1 组合构建缺优化器

`PortfolioBuilder` 是"封顶 + 缩放"启发式（`max_symbol_weight` 20%、`max_industry_weight` 40%、`cash_reserve` 5%、整手取整），不是优化求解。没有均值-方差、风险平价、Black-Litterman，也没有跟踪误差/换手约束。适合 v1，但做不了风险预算和风格择时。

### 4.2 策略层单薄

只有等权 top-N 选股、ETF 轮动、指数择时。缺行业轮动、风格择时、多策略组合、波动率目标。`MultiFactorStrategy` 是等权百分位排名，没有权重优化（按域设权重目前还没有被策略层消费）。

### 4.3 训练/选参未产品化

roadmap 明确："训练、选参、窗口到运行的不可变绑定仍由调用方管理"。没有参数搜索、滚动窗口训练、样本外 walk-forward 的编排。

### 4.4 实盘边界：永久不在项目范围

有意为之且不再推进：本项目不接入真实账户，不做实盘自动化交易，因此不存在真实账户适配器、券商对账与 kill switch 的建设计划。系统产出止于研究结论、选股名单、组合持仓方案、风险预算与持仓推演，实际下单由人工在外部券商终端完成。

## 5. 建议的落地优先级

| 优先级 | 动作 | 解决 |
| --- | --- | --- |
| P0 | 接估值数据源，填 `valuation_snapshot` | 2.1 |
| P0 | 建因子批量计算管道（全 universe × 全历史），并接入 scheduler 每日增量 | 2.2、2.3 |
| P0 | 把每日闭环串起来：sync -> factor -> signal -> rebalance -> risk -> paper，写进 scheduler | 2.3 |
| P1 | 接 system 表：ingest 写 `job_log`、质量校验产出 `data_quality_issue`、配 `data_source` | 3.2 |
| P1 | 回测补 A 股约束：涨跌停/停牌/印花税/T+1/容量 | 3.3 |
| P1 | 系统化因子检验：批量算 IC/分组/换手/衰减，落 `factor_profile` | 3.4 |
| P2 | 补另类数据真实来源（北向/融资/龙虎榜/一致预期） | 3.1 |
| P2 | 跑通一次完整新执行闭环（plan -> equity -> risk -> approval -> batch） | 3.5 |
| P3 | 组合优化器、策略层扩展、训练编排 | 4.1-4.3 |

## 6. 结论

"零件"造得不错（数据底座、因子框架、回测/组合/风控/模拟盘都有首版），但还没"组装成一台能每天自己转的机器"。最关键的三件事是：把估值数据采进来、把因子批量算出来并每日增量、把整条日闭环调度起来。这三件做完，系统才算真正"跑起来"；其余是让它"跑得可信、跑得好"。
