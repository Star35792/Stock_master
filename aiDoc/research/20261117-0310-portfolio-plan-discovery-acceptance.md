# 组合草案发现验收与兼容修复

承接[草案发现决策](20261117-0129-portfolio-plan-discovery.md)。本轮收尾该功能，不扩展产品范围。

## 实际页面证据

以 backend 为工作目录临时启动 8001 API（lifespan off）与 5173 Vite，Chrome 访问真实持仓页。首次列表返回 500，原因是当前主库缺少 ORM 的 style_risk 列，而列表错误地选择了整个记录。页面正确显示列表失败和手输 ID 回退提示。

仓储改为只加载摘要使用的 id、name、as_of_date、total_equity、code_version、created_at，并对未加载列启用 raiseload。没有修改数据库 schema，也没有运行初始化或迁移。内存 DuckDB 回归使用缺少详情列的非空表，验证 Service 序列化与 Decimal 金额精度。

修复后点击刷新草案，真实 API 返回 200，页面显示“尚无组合草案”，点击“组合页”进入 /portfolio 创建表单。未提交草案、账本或流水。由于真实库无草案，非空分页与选择由组件测试覆盖。

金融复核指出只显示月日不能准确区分跨年草案；选择项和已选摘要改为直接展示 API 的 YYYY-MM-DD 日期，避免时区转换与年份丢失。

## 验证范围

前端统一门验证组件测试、类型检查和生产构建；后端定向测试验证分页、摘要序列化、参数约束与旧结构兼容，Ruff 检查修复文件。独立产品/后端及金融复核结论保留在本轮会话，不把自查视为独立复核。

临时服务验收后关闭。测试数据仅在内存中；既有 frontend/dist 更新为 5 个构建文件，未创建数据库备份或额外事实源。保留工作区既有未提交修改，本轮不暂存、不提交。
