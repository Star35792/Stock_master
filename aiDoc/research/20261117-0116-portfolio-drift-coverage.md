# 组合偏离覆盖草案外持仓及逐仓报价日期

## 决策

组合偏离是草案与**整本**真实持仓账本或模拟账户的只读对照。结果先列草案目标，再按代码排序列出草案外的非零持仓。草案外持仓的目标权重和目标数量均为 0，但增持、减持或持有方向仍按请求阈值判断；因此低于阈值的草案外持仓可能显示“持有 / 目标 0”，表示当前偏离尚未触发调整提示，不代表草案包含该标的。最大偏离和超阈值计数覆盖全部结果行。

每行返回 `in_plan` 和该持仓实际使用的 `price_as_of`。顶层 `price_as_of` 仍为所有已定价持仓中的**最晚**报价日，不能当作共同估值日。草案中尚未持有的目标没有逐仓报价日期，且在没有持仓可信价格时不提供整手目标数量。

页面在账本刷新、记账或删除流水、修改现金、草案 ID 或阈值变化及新检测开始时，立即清空旧结果并使在途旧响应失效，避免把旧方向用于当前持仓。

任一非零持仓缺可信未复权收盘价时，整个偏离请求继续以 `portfolio_drift_missing_trusted_prices` 阻断；成本替代估值不能生成方向。较早但仍被市场可信层接受的报价继续参与计算，页面指出其日期，供人工判断停牌或行情延迟等原因。方向和目标数量均不验证当日可交易性，也不产生真实或模拟订单。

## 原因与验收

旧结果只遍历草案目标。草案外持仓虽参与总权益和现金权重，却不出现在结果及最大偏离、超阈值计数中，可能隐藏最大的风险暴露。逐仓报价日缺失又会让顶层最晚日期被误读为全部持仓的估值日。此次仅扩充读时推导和响应，不改账本事实源、行情资格或落库数据。

验收覆盖：草案外非零持仓稳定排序并进入统计；零数量历史持仓不进入结果；逐行日期和 HTTP 响应一致；缺价继续整体阻断；既有草案目标的整手数量、阈值方向和只读边界保持原口径。回退为撤销响应增量与行扩充，SQLite、DuckDB 均无需迁移。
