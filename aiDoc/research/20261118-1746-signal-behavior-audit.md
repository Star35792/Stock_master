# 信号行为审计与首批吸收落地

## 决策与交付边界

承接[三项目吸收方案](../plans/20261118-1711-external-project-absorption-plan.md)的 C02/C03（A1）。吸收 TickFlow 的“截断/扰动未来输入、比较过去输出”方法，按照本项目 Decimal、不可变输入、研究合同和 Vue 工作台重写；未引入外部项目运行时或复制其第二套数据库。

用户随后要求同时落地前后端，因此本次将原方案的“仅内存、暂不新增 API”推进为**只读计算 API + 回测详情入口**。仍不持久化报告，不改写旧运行，也不把三十项候选登记为已交付。

已交付：通用内存审计器、普通因子选股运行适配器、POST 接口、详情面板、反例测试及页面验收。A2 此次只有下述证据矩阵与合成账本合同；现金分红会计、送转及其生产数据接入仍未交付，`corporate_action_policy=reject` 保持有效。B–H 按原方案准入条件继续排队。

## 核验流程与证据

入口：`POST /api/v1/backtests/runs/{run_id}/signal-audit`，无请求体、无用户脚本。前端在 `/backtests/runs/{runId}` 成功运行详情中手动启动，挂载时不计算。

1. 研究仓储先读取合同 JSON 字符数；超过 1,000,000 字符不载入完整合同。仅在短研究锁内复制运行，然后关闭 Session、释放锁。
2. 要求成功运行、完整选股参数和原始 `signals`、支持的 `strategy_factor_frame_v1`。记录的代码版本须等于当前后端 `app/**/*.py` 内容摘要；自定义/未知或旧版本均不可核验。未支持训练窗自动选参和附带组合约束的运行。
3. 按配置读取可信因子（控制面/温层孪生路径），SQL 在物化前应用剩余预算加一；多个因子共享预算，不截取大运行的一部分冒充完整审计。当前因子 frame 的**完整 snapshot**须与原运行一致。
4. 冻结当前证券类型与非日频调仓日历，按原参数重建策略，并与原运行**完整信号集合**逐项核对；显式零权重退出与缺失信号不同。证券类型和日历未绑定原运行摘要，因此即使信号一致，也不声明完整历史回放。
5. 固定输入下重复重算；最多取首/中/末三个非末日截止点，分别截断未来观察值、对未来有效数值施加确定性逐行扰动，只比较截止点及以前信号。最后再做相同输入重复检查。
6. 结束最初主库读取事务，再读取因子、证券类型和日历，并重新计算代码摘要；发现变化撤销可核验结果。温层连接在成功/异常路径均关闭，不改变 release 或父链。

`StrategyFactorFrame.snapshot()` 仅覆盖因子值、因子身份、观察日期与因子 run IDs；不覆盖证券类型、日历、策略参数、代码或行情到因子的计算。因此报告固定 `scope=factor_frame_to_signal`、`historical_replay_verified=false`。`input_verified` 表示因子摘要核对，不代表全部历史输入已还原；`baseline_matches_run` 表示本次重建的完整信号与原记录一致。

通用回调审计器可由内部代码提供更上游的计算范围；测试中的故意未来位移、全样本归一化均从受扰动样本重新计算。运行适配器直接消费已落地因子，无法检测此前在因子计算或预处理中引入的泄漏。缺失值政策、公告首次可得时刻、历史修订、幸存者偏差、成交/费用/收益和公司行为均在本次核验范围之外。

## 状态、资源和页面

| 状态 | 含义与展示 |
| --- | --- |
| `passed` | 抽样前缀未发现差异；显示“抽样通过”，不授予策略或收益资格 |
| `failed` | 改动未来输入后过去信号变化；展示有界差异示例，缺失和合法零分别显示 |
| `insufficient` | 证据、版本、规模、可比较信号或时间预算不足；显示“不可核验”及原因 |
| `error` | 回调异常/无效输入或相同输入可观测不稳定；不能直接归因为未来函数 |

不存在的 run 返回 404；已有审计计算或研究库锁超时返回 409；HTTP 错误与报告状态分开。页面支持重试、切换 run 清空及忽略迟到响应。“停止等待”只终止浏览器等待，服务端可能继续计算。

单 worker 内一次审计计算；最多 20,000 输入行、20,000 信号、252 观察日、8 因子、366 自然日窗口、3 截止点、9 次重算、12 条差异示例。10 秒为**协作式计算预算**，在读取/回调边界检查，不能打断正在执行的 SQL 或 Python 回调，不承诺硬实时取消。报告记录实际输入改动行数；没有实际改动的扰动不算有效覆盖。

计数表示**本次载入/重算**，不能用版本不符时的零计数推断原运行没有数据。报告只在本页保留，刷新或离开页面后清除，无自动缓存、schema 变化或资格回写。

## A2：事件证据矩阵与合成账本合同

以下是下一切片的准入合同，**不是现有事件引擎能力**。源码核对 `CorporateAction` 已有 `source_event_id`、`ex_date`、可空的 `record_date/payment_date` 和 Decimal 数额，但没有结构化的公告/首次可得时刻、修订身份、税务政策和独立事件会计账本。`raw_payload` 中存在某字段不等于已通过可信发布。此处未查询生产库，不把历史行数当成本日核实结果。

| 事件/条件 | 首片验收所需证据 | 当前决定 |
| --- | --- | --- |
| 纯现金分红 | 事件身份/修订、公告/首次可得时刻、登记/除息/到账日期、每股单位、税前/税后定义、持仓资格与税务情景 | 合同已列出；引擎和可信数据准入待实施，继续 reject |
| 日期缺失或跨源冲突 | raw 证据、冲突裁决与修复审计、版本隔离 | 不猜测到账日或用采集日替代，拒绝 |
| 重复/修订事件 | 同事件/同内容幂等，新版本不重写旧研究引用 | 不重复入账，修订切换规则待实现 |
| 送转/拆合股、配股、混合事件 | 数量变更、可卖时刻、取整及对价的独立合同 | 不纳入首片，不用通用倍率模拟现金与持仓 |
| 期初持仓、持有期税务未知 | 已验证的期初批次和登记日资格，显式税务假设 | 只能独立标明假设情景，不声称真实税后净收益 |

合成已知解（无交易费、无税，金额为 Decimal 的**研究情景**）：登记日持有 100 股、现金 1,000、股价 10；每股分红 0.20。登记日后、除息日前无交易，除息日价格假定 9.80。

| 时点 | 可用现金 | 股数 | 应收股息 | 市值 | 总权益 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 登记日收盘 | 1,000.00 | 100 | 0.00 | 1,000.00 | 2,000.00 |
| 除息日确认应收 | 1,000.00 | 100 | 20.00 | 980.00 | 2,000.00 |
| 到账日前以 9.80 全部卖出 | 1,980.00 | 0 | 20.00 | 0.00 | 2,000.00 |
| 到账日结清应收 | 2,000.00 | 0 | 0.00 | 0.00 | 2,000.00 |

应收不能在到账前用于买入；清仓不抹去已取得的应收；分红不算外部入金。下一切片需把本例和登记日前后买卖、同日顺序、期末未到账、重复、修订、单位与取整变成独立测试后，再评审政策版本与 schema。该表没有运行真实分红会计，也不预先授权发布生产事件。
