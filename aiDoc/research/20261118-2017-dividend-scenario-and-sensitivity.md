## A2：合成现金分红账本

入口为 `POST /api/v1/strategy-research/cash-dividend-scenario`，研究首页展开「现金分红情景账本」后手动计算。输入固定 `input_kind=synthetic`、`price_basis=unadjusted_synthetic`，价格和金额使用精确十进制字符串；拒绝浮点、布尔金额、非有限值与超精度输入。

处理顺序与政策固定为 `synthetic_cash_dividend_v1`：

1. 期初现金与已结算股数形成初始权益；日期严格递增，窗口最多 366 个自然日。
2. 登记日收盘、处理当日全部给定成交后确定资格数量，须满足起日 ≤ 登记日 < 除息日 ≤ 到账日。窗口内这三个事件日必须明确列入价格日，不推测遗漏日期。
3. 除息日按已登记数量确认税前股息，按固定假设税率计提税额与净应收。政策 `fixed_assumed_rate_at_ex_v1` 不是实际持有期税法或真实税后收益估计。
4. 到账日把净应收转成可用现金；同日先确认除息应收、再到账、再按输入顺序处理给定成交。到账前不能以应收融资买入；登记后清仓不抹去已取得的应收。
5. 期初及上一处理日股份假定已结算；当天新买股数不可当天卖出，不允许负现金或卖空。输入成交不证明涨跌停、容量、流动性或实际可成交，非连续日期仅为给定处理日。
6. 每事件税前股息、假设税额及每笔成交金额按 `ROUND_HALF_UP` 取到分，净额为已取整税前额减税额；估值保留输入价格精度。税前额 = 假设税额 + 净额，到账只在现金与应收之间移动，股息不算外部入金。

同事件 ID、同修订及同内容重复输入幂等，响应记录忽略数；同 ID 内容或修订冲突整体拒绝，要求调用方先选定一个版本。没有新版本静默覆盖旧事件的通道。事件输入不包含公告/首次可得时刻，因为该工具仅为合成情景，不赋予真实证据资格。

限制为一个标的、32 个事件、366 个价格日、500 笔给定成交、最多 1,000 万股。只在内存计算，不建立持久缓存或 schema；输入规范化后生成 SHA-256，重复事件与等值 Decimal 表达不改变身份。API 参数或业务校验失败返回 422，响应金额仍为字符串。

独立已知解：初始现金 1,000、100 股、价格 10，每股股息 0.20，除息价 9.80，无税无费。除息现金/应收/市值为 1,000/20/980，权益 2,000；到账前清仓为 1,980/20/0，到账后现金 2,000。假设税率 20% 时净应收 16、税额 4，期末权益 1,996；期末未到账时净应收仍计入权益。

## B：既有运行单轴与双轴比较

入口为 `POST /api/v1/backtests/runs/sensitivity`，回测列表展开「参数敏感性比较」。可载入当前勾选运行，也可手工输入失败运行编号；首项可预填为基准，用户可显式改选。请求包含 2–64 个不同正整数运行编号、列表内的基准编号、一或两个不同扫描轴，以及可选研究假设、接受说明和停止说明。

支持 `top_n`、`rebalance_interval`、`coverage_ratio`、`minimum_score`、`invested_weight`、`commission_rate`、`slippage_bps`。数值先校验有限性、位数/小数位和轴范围，再规范化，避免极端指数膨胀。空覆盖比例/最低分数保留为明确的「未设置」，不能补零。

研究仓储先查询合同 JSON 字符数，单项最多 1,000,000 字符、整批最多 8,000,000 字符，再投影载入合同、运行头和已保存绩效。超限或不存在的运行保留为未归类原因；不载净值、交易、持仓或绩效暴露大 JSON。短研究锁与 Session 在复制完成后释放，之后内存计算；锁超时返回 409。

同一日期窗口按扫描值分候选；双轴以各轴观测值的笛卡尔积补出缺失组合，候选 × 窗口最多 256 格。候选按数值确定性排列，不按收益排列。同候选同窗口多条运行标记 `duplicate`，不自动选最好一条；缺格为 `missing`；失败、缺已保存绩效、非有限/非 Decimal 指标或运行收益与绩效收益不一致为 `unavailable`。

`controlled`（页面「合同一致」）仅表示以下**已记录字段**一致且符合支持合同：

- 普通 `factor_selection` 参数完整有效，运行日期与合同相符，合同与运行代码身份一致；训练窗自动选参首片不支持受控比较。
- 市场组成摘要声明 `trusted_market_slice_v1`、可信且运行后摘要相同；因子摘要为 `strategy_factor_frame_v1`、有正行数和有效 SHA-256。设定基准行情时须有已冻结基准摘要。
- 同窗除声明扫描轴外全部固定参数、策略/运行代码和绩效计算版本、期初资金相同，市场/因子/基准组成身份相同。整体 `data_version` 不作为共同输入的替代证据。
- 同窗基准候选须唯一、成功且保存绩效有效。基准自身指标异常或收益不一致会传递给候选，不能生成相对错误基准的差值。
- 跨窗允许开始/结束、测试/训练日期和窗口 ID 改变；其他固定合同和代码仍与选定基准一致。窗口内这些元数据继续严核，不忽略费用或其他非扫描变化。

其余有效绩效可作为 `exploratory` 展示并给出原因和最多 30 个固定字段差异，不生成受控差值。旧合同缺身份时不尝试从当前因子、行情或代码回填。

记录的因子摘要没有完整绑定选股前证券类型映射和非日频调仓日历；相同已记录摘要不证明全部历史输入相同，也不认证完整 PIT、无泄漏、独立留出集或收益资格。本文没有增加这种认证。市场切片不同但可能存在共同输入的旧运行仍保守显示探索性，不以推断补证据。

单轴只画合同一致实测点，缺格不连线；双轴热力图保留缺格和状态，不插值。各候选仅在全部所选窗口合同一致且无未归类运行时输出中位、最差、范围；零收益有效，不用真值判断过滤。窗口收益不复利拼接，重叠窗口也不解释为独立样本。

报告固定 `selected_run_sensitivity_v1`、`research_only=true`、`ranked=false`、`recording_stage=retrospective`。假设/接受/停止说明是事后记录，不能冒充历史预注册；JSON 导出包含本次请求、运行引用、输出、原因与输入合同哈希，**不是离开原数据库仍能独立恢复的完整实验快照**。不存入研究库，不修改旧运行，不晋级策略。
