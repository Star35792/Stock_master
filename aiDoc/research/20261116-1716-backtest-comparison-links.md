# 回测比较链接与研究状态恢复

## 决策

回测页把所选成功运行按顺序写入 URL 的 `runs` 查询参数，首项仍为基准。例如 `/backtests?runs=10,13`。勾选、移除、清空及更换基准使用 `router.replace`，不会让每次操作占用一条浏览器历史。详情链接携带当前选择，详情页返回时透传，刷新或复制链接后也可恢复。

恢复只接受 1–20 个互不重复、安全整数的正数编号。单项用现有详情 GET 核验成功状态；多项用只读 `compare-preview` 核验全部成功运行并恢复预览，不能把失败项静默剔除或改变基准。响应必须与链接 ID 和顺序完全一致。无效或已失效链接保留原 URL、显示错误，并可清空链接选择。同页导航修改 `runs` 时也重新恢复；恢复请求的旧响应不得覆盖新链接或后续本地选择，排队中的本地 URL 写入不能覆盖新链接。快速勾选的 URL 更新顺序受控。列表接口失败时，已恢复的比较仍可见。

URL 只保存运行编号，不保存绩效数值或合同副本；打开链接时重新读取当前研究库。已有研究库的运行产物不回填或重写，严格比较、漂移检测与金融计算均不变。查询参数不构成结果版本锁定，研究结论仍须以运行数据、代码和输入快照为准。

## 评审与验证

触发 T2：关键研究工作流和导航状态变化。产品独立复核提出详情往返、无效链接可清空、异步恢复竞态及同页导航同步等 P1；修正后复查确认全部关闭，未发现剩余 P0/P1。主代理核对 URL 不含敏感研究产物、只读恢复、运行失败显式报错、浏览器历史行为与回退方案。删除本页 URL 同步与恢复逻辑即可回退，无数据库迁移。

前端定向测试覆盖恢复顺序、单个成功运行、基准更换、无效和失败运行、同页导航、待恢复时导航到空链接、旧响应、快速勾选 URL 顺序及详情链接即时参数。统一 CI 通过：后端 1635 项通过、2 项跳过，前端 36 项通过，类型检查和构建成功。实际页面和窄屏走查仍受浏览器 URL 安全校验阻断，作为验证缺口保留。
