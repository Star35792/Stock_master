# 研究比较中的策略合同差异

## 现状与决策

研究库真实运行 10/13 的基础口径一致，收益差约 +4.70 个百分点。此前预览能给数值差，却没有列出两次研究假设的具体变化。只读核查发现两项的 `factor_specs`（包括三个因子方向）和运行证券池均不同；这使用户需要逐条打开完整运行参数才能解释研究设计。

`POST /api/v1/backtests/runs/compare-preview` 每项新增 `strategy_contract` 与 `strategy_differences`。前者只选取策略标识、因子配置、选股数量、信号滞后、调仓、组合约束、基准、允许证券类型、运行证券池、权重/评分政策、交易手数、训练与验证窗口字段、训练产物编号，以及策略输入与市场输入快照 SHA-256；不复制完整 `signals`、交易或数据快照。后者按所列字段与首项基准逐项比较，证券池按成员集合比较而非列表顺序。字段缺失显示“未记录”。页面折叠展示不同字段的基准值和本项值；证券池先显示交集、新增、移除数量及少量示例，完整代码按需展开。数值差仍保留先前基础口径门槛。

差异是研究合同检查线索，不说明某个字段造成多少收益变化；尤其当因子、股票池和市场输入同时变化时不可作单因素归因。同一旧 `data_version` 也可能有不同市场输入快照，页面将其单列。训练产物编号只作血缘线索，不等于训练内容已核验。所列字段并非完整可比性证明，历史时点资格与其他参数仍需审阅。严格 `compare` 和 `drift` 不受影响。

## T2 评审与验证

触发原因是公共响应合同和关键研究工作流变化。项目现状为单机单用户、82 条成功历史运行，运行参数中混有大量逐日信号；只返回选定字段可避免在比较 API 中重复大块研究产物。回退为删除新增响应字段及折叠面板，研究库无写入或迁移。风险为用户把相关差异误读为因果解释，页面和文档已明确禁止。完整策略合同仍未版本化，未来若要严格归因或自动排名须另行设计。

产品、金融、技术三个独立只读复核均未见 P0。产品的证券池展示 P1 已用交集/新增/移除摘要与折叠的完整代码解决；金融的市场输入快照 P1 已纳入差异，复查通过；技术确认不新增逐项 SQL，当前最大相关字段约 5.7 KB/运行。完整证券池仍随 API 返回，折叠只降低页面噪声；未来增长时的响应大小上界列 P2。真实研究库只读调用中，10/13 返回 `strategy_differences=['factor_specs','symbols','data_snapshot_sha256']`，证券池交集 7、候选新增 375、移除 320，只读差异也显示三个因子方向变化。后端测试验证差异、市场/训练血缘和排除逐日 `signals`，前端测试验证字段名、方向与证券池摘要。仓库级 `scripts/ci_check.py --scope all` 最终退出码 0（后端 1635 项通过、2 项跳过；前端 31 项通过并构建成功）；此前一次全量运行中无关的报告文件替换用例偶发失败，隔离运行和随后全量复跑均通过。实际页面布局与展开交互仍因浏览器 URL 安全校验未验收，作为 P1 验证缺口，当前不提交。README API 面、路线图与 Reference Map 已同步。
