# 产品与投资者视角评估

> 评估日期：2026-09-19
> 评估范围：Stock Master 后端架构、数据湖、因子工厂、研究回测、组合风控与模拟盘闭环
> 视角：产品经理 + 资深投资者 / 量化研究员

## 1. 总评

Stock Master 是一个工程态度认真、架构分层清晰的量化投研中台。当前已完成从 raw → market → factor → research/backtest → portfolio/risk 的最小闭环，并在可复现性、审计、研究合同化上建立了良好基础。

但从投资产品化角度看，系统仍处于 **"能跑 demo" 到 "能相信结果" 之间**。核心矛盾不是功能不够多，而是金融正确性的硬门槛尚未全部落地。在以下问题解决前，系统不适合直接指导实盘资金：

- 财务/基本面因子的时点正确性（look-ahead bias 风险）
- A 股真实交易成本（印花税、最低佣金、涨跌停、停牌）
- 滚动 walk-forward 验证（而非单期 holdout）
- 组合层面的风险预算与风格暴露

## 2. 产品经理视角

### 2.1 定位与差异化

系统定位是 **API-first 的量化投研基础设施**，目标用户是量化研究员、策略开发者或基金公司中台团队。差异化亮点是：

- 可复现的研究合同（code_version / data_version / 输入快照）
- 分层可信数据湖与血缘追踪
- 模拟盘执行的审计与幂等

但当前没有清晰回答：用户为什么不用米筐 / 聚宽 / 自建 Python 流水线？对独立研究员和小团队门槛过高；对大型机构又缺少多租户、权限、SLA 等企业级能力。

**建议：** 明确 GTM 优先级。若目标为机构中台，补齐多租户、权限、审计、SLA；若目标为个人/小团队研究员，优先做 Jupyter/Notebook 集成和一键策略模板。

### 2.2 路线图执行节奏

V1 → V7 的分层路线图合理，但当前存在 **"同时挖多条战壕"** 的风险：

- V4 刚完成单次回测合同化
- V5 已推进组合构建、风险评估、模拟盘执行
- V6 运维工作台已收口

研究核心尚未稳，交易和运维就先跑起来，会导致回测结果还没经过 walk-forward 验证就被用于模拟盘，模拟盘策略又只有单一因子选股模板。

**建议：** 把 V4 做透再做 V5。walk-forward 滚动样本外验证和训练产物血缘应是 V4 的硬门槛，而非 V5 的后续增强。

### 2.3 功能覆盖与杀手级场景

当前功能覆盖广但深度不足：

| 模块 | 现状 | 差距 |
|---|---|---|
| 数据湖 | raw/market/factor + curated parquet | 缺实时增量、多源冲突自动仲裁 |
| 因子 | 82 个定义 + 横截面变换 | 多为代理变量，可预测性未验证 |
| 回测 | 事件引擎 + 研究合同 | 仅日频、单一模板、费用模型简化 |
| 组合 | 目标权重 + 约束 | 缺均值-方差优化、风险预算、跟踪误差 |
| 风控 | 事前单标/行业/回撤/容量 | 缺组合风险模型、压力测试 |
| 模拟盘 | paper-only 原子执行 | 缺异步/部分成交、券商对账 |

**建议：** 选一个垂直场景打透，例如 **A 股指数增强**，把指数成分历史、行业中性、风格约束、跟踪误差、benchmark 比较做完整，作为标杆案例再横向扩展。

### 2.4 可复现性的用户体验成本

研究合同、版本、快照、SHA-256 校验是工程亮点，但：

- 用户需手动传 `code_version`、`data_version`
- 滚动窗口只能规划，不能执行
- 验证报告需调用方自行指定 run_ids 聚合
- 训练产物明确标记 `training_artifact_verified=False`

可复现性仍依赖用户纪律性，而非平台强制保证。

**建议：** 把可复现升级成平台契约：自动捕获版本、提供一键重跑 API、训练产物必须进入不可变存储才能被引用。

### 2.5 前端与 API 分工

当前前端主要是运维工作台，研究核心交互（因子探索、策略构建、回测调参、绩效对比）尚未在 UI 闭环。

**建议：** 资源有限时，优先把 API 和 CLI/Notebook 体验做扎实，前端先做只读监控，不要追求大而全。

## 3. 资深投资者 / 量化研究员视角

### 3.1 防未来函数做得较好

- 信号次日开盘执行
- `StrategyFactorFrame` 每次只暴露 `as_of_date == signal_date` 的单日横截面
- 跨日决策 frame、重复观测、未来行均 fail-closed
- 回测消费可信 `market` 和 `factor` 层

但 **财务/基本面因子的时点问题** 尚未完全解决。当前因子仍可能按报告期结束日或披露截止日赋值，这会系统性地提前获得未来信息。由于穿越在训练期和测试期同时存在，单期 holdout 无法发现该问题。

**硬门槛：** 所有基本面因子必须能追溯到「公告日或首次可得时间」，否则不得进入生产因子集。

### 3.2 回测成本模型低估 A 股实盘摩擦

当前费用模型：

- 双边佣金 0.03%
- 滑点 2 bps
- 无卖出印花税
- 无最低佣金
- 无交易所过户费/规费
- 无冲击成本

A 股实际：

- 卖出印花税 0.05%（2023 年减半后）
- 佣金通常 0.025% 但最低 5 元
- 过户费、规费
- 小盘股/ETF 实际滑点可能远高于 2 bps
- 涨停买不到、跌停卖不出

**结论：** 当前回测系统性高估收益，尤其对高换手策略。`linear_commission_v1` 不能用于评估实盘可行性。

### 3.3 A 股特殊风险未充分建模

回测引擎要求目标日有可信未复权 bar，否则拒绝运行，但未处理：

- 涨停无法买入
- 跌停无法卖出
- ST/*ST 涨跌停限制
- 停牌日无行情
- 退市整理期
- 新股/次新股特殊规则
- 解禁、增发、配股导致的可交易股份变化

**结论：** 没有涨跌停约束的回测对 A 股缺乏实际意义。「每天买入前 20 强势股」在回测中会表现极好，因为现实中很多强势股票买不到。

### 3.4 策略模板单一

当前主要为 `MultiFactorStrategy` 因子选股。缺少：

- 指数增强（跟踪误差约束）
- 市场中性 / 配对交易
- CTA / 趋势跟踪
- 套利（跨期、跨品种、ETF 申赎）
- 行业轮动
- 资产配置（股债商）

**建议：** 不要急于扩展模板数量，先把策略抽象层做好：信号生成 → 组合构建 → 风控 → 执行 拆成可插拔组件。

### 3.5 风险模型停留在订单级规则

`PreTradeRiskEngine` 提供：

- 单标权重上限
- 行业权重上限
- 回撤止损
- 成交额参与度
- 价格偏离

缺少：

- 组合层面波动率 / VaR / 预期回撤
- 风格因子暴露（Barra 风格：市值、价值、动量、质量、波动、流动性）
- 行业集中度风险
- 基准跟踪误差
- 压力测试 / 情景分析

**结论：** 单标上限无法防止组合集中在某一主题（如 30 只股票全在 AI 板块）。

### 3.6 样本外验证不足

- `out_of_sample` 只支持单期 holdout
- 滚动窗口仅规划，不执行
- 验证报告只读聚合，调用方自行指定 run_ids

**结论：** 一期 holdout 不足以证明稳健性。需要滚动 walk-forward 评估策略在不同市场环境下的表现。

### 3.7 因子有效性未系统验证

当前 82 个因子中，是否通过以下检验尚不明确：

- IC / Rank IC 稳定性
- 分组收益单调性
- 不同市场状态下的有效性
- 小盘 / 大盘 / 价值 / 成长风格下的有效性
- 因子相关性矩阵与冗余诊断

**结论：** 堆因子不等于有 alpha。很多因子可能是风格暴露（小市值、高 beta），风格反转时会大幅回撤。

### 3.8 数据源合规与稳定性

依赖来源：

- HiThink dump（同花顺 iFinD？）
- Eastmoney
- AKShare
- 未来可能 QMT

风险：

- 付费数据源的许可范围与商业化限制
- 免费/半公开接口的稳定性和合规性
- 实盘所需的实时性与完整性

**建议：** 明确数据合规边界，建立数据 SLA 监控（延迟、缺失率、源冲突率），对免费来源做 graceful 降级。

## 4. 战略优先级建议

### P0：必须立即加深

1. 财务/基本面因子时点正确性
2. A 股真实交易成本与可交易性（涨跌停、停牌、ST）
3. 滚动 walk-forward 验证
4. 组合风险预算与风格暴露

### P1：保持但不扩大

5. 模拟盘与风控（V5 已不错，等研究核心更稳后再扩展异步成交、券商对账）
6. 因子数量（先验证已有 82 个，再新增）

### P2：暂缓

7. 实盘接入（V7），在研究正确性未解决前不启动
8. 大而全的前端，先做 API + CLI/Notebook

## 5. 结论

Stock Master 的工程底座扎实，但投资逻辑还处在成熟早期。当前最大风险是金融正确性缺口可能被大量功能掩盖，导致使用者对回测结果产生虚假置信度。

**下一步主线建议：** 把 V4 研究可复现性做硬——公告日/首次可得时间、真实成本、涨跌停停牌、滚动 walk-forward、风险预算。这五项完成后，才值得大规模接入真实资金和复杂策略。
